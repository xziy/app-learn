# Unitool: читалка книг из app-learn и Superizer 0.8.2

Задание для сессии, которая ведёт Unitool. Из этого репозитория до исходников Unitool не дотянуться, поэтому всё, что ниже, —
его сторона.

## Что появилось

- **app-learn `apps/books`** — читалка книг, переведённых по Драгункину (D22, D23 в `.ai-notes/README.md`). Класс `BooksApp`,
  id `books`, конфиг `BooksConfig(download: String?)`, ссылка `<схема>://app/books/download?url=…`.
- **Книги в git не идут:** репозиторий публичный, тексты под авторским правом. Сборка Unitool получит пустую полку, а книги
  человек скачивает сам: «+» на полке → ссылка на архив `.book.tgz` или QR-код → «Скачать».
- **Superizer 0.8.2** — три необязательных сервиса, контракт не меняется (по-прежнему 6), в ABI только добавления:
  - `AppFolder` — папка приложения, которую видит человек. На iOS это `Documents/<id приложения>` хоста.
  - `FileDownloader` — файл по HTTP байтами, с пределом размера. `KtorFileDownloader` на клиенте хоста.
  - `QrScanner` — та же камера, что у экрана «Активировать» (`qrScanner { … }`), теперь и для приложений.

  Билдер даёт их сам, если хост не зарегистрировал свои. Подробно — `docs/05-host-api.md` Superizer, раздел «What a host offers
  apps without being asked (0.8.2)», и `CHANGELOG.md`.

## Что сделать

1. **Superizer → 0.8.2.** Если Unitool подменяет сеть через `network(…)`, загрузчика не будет: тогда зарегистрировать его
   самому — `service(FileDownloader.Key, KtorFileDownloader(client))`. Если папки должны лежать не там, где по умолчанию, —
   `appFolders(root)`; `appFolders(null)` их выключает.
2. **Подключить `BooksApp`** так же, как подключён `LearnApp`: модуль `:apps:books` из `external/app-learn`, `register(BooksApp())`,
   при желании — в `home(…)`. У модуля есть Android-цель (как у learn, D18), веб-цели нет: в web-сборку его не включать.
3. **iOS, `Info.plist` хоста** — чтобы папка была видна в «Файлах» («На iPhone › Unitool › books»):

   ```xml
   <key>UIFileSharingEnabled</key><true/>
   <key>LSSupportsOpeningDocumentsInPlace</key><true/>
   ```

   Без них читалка работает, но человек не найдёт свои книги и не сможет положить архив в папку сам.
4. **Камера.** Если `qrScanner { … }` уже задан для «Активировать», читалка получит его сама. Камера должна показываться поверх
   открытого приложения: читалка открыта на весь экран (`AppChrome.fullscreen`), когда человек нажимает «Прочитать QR-код».
5. **Ссылки на iOS.** QR-код книги несёт `unitool://activate?a=books&c=<base64url {"download": "<адрес архива>"}>`
   (`pack_book.py --scheme unitool`). Его понимают экран «Активировать» и сканер читалки. Чтобы его открывала и обычная камера
   iPhone, схема `unitool` должна быть в `CFBundleURLTypes`, а пришедший URL — уходить в `superizer.route.deliver(link)`.

## Как проверить

- Собрать архив: в app-learn, `../.claude/skills/dragunkin-text`,
  `python3 scripts/pack_book.py phosphorus --url <адрес> --scheme unitool --qr`, положить `phosphorus.book.tgz` по адресу.
  Можно взять любую книгу: в архиве только `meta.json` и `book.json`.
- В Unitool: «Книги» → пустая полка с кнопкой «Загрузить книгу» → ссылка → «Скачать» → «„…“ на полке» → «Читать».
- «Файлы» → «На iPhone» → «Unitool» → «books»: там `phosphorus.book.tgz`. Удалить его там — книга уйдёт с полки при следующем
  открытии. Положить туда другой архив — он появится.
- QR-код со снимка `--qr` через «Активировать» и через камеру iPhone открывает экран загрузки с этим адресом.
- После «Сгрузить приложение» и повторной установки книга на месте. После полного удаления — нет: так устроена iOS.

Что проверено в app-learn и Superizer: тесты на desktop (папка во временном каталоге, загрузчик на mock-движке Ktor, сканер,
экран загрузки, архивы, сделанные `java.util.zip` и `pack_book.py`); компиляция klib для iosArm64, Android и web. На устройстве —
ничего: ни папки в «Файлах», ни камеры, ни ссылок.
